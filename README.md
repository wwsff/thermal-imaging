# RTOS_LCD 热成像终端

基于 STM32F407VET6、FreeRTOS、LVGL 和 MLX90640 的便携式热成像终端。项目使用 320 × 240 TFT 触摸屏显示热图，可切换多种色板、显示中心温度与热点温度，并通过 CW2015 显示电池电量。

当前软件版本为 `V3.07`。本仓库用于保存可直接编译、继续开发和再发布的完整工程源码与原版 EPRO 硬件设计。

## 当前实现效果

### 开机自检

上电后先进入黑色启动界面，显示项目 LOGO、自检项目、详细状态、进度条和百分比。

自检顺序如下：

1. 初始化 LCD、LVGL 和触摸输入。
2. LED1、LED2、LED3、LED4 依次低电平点亮约 120 ms，然后全部熄灭。
3. 检查 MLX90640 是否在 I2C 地址 `0x33` 应答，并完成刷新率、棋盘模式、EEPROM 参数等初始化。
4. 检查 CW2015 是否在 I2C 地址 `0x62` 应答，退出休眠后读取版本、电压和电量。
5. 显示 `MLX:OK/FAIL` 和 `CW:OK/FAIL`，随后进入热成像主界面。

自检期间热成像采集任务保持等待，避免与初始化任务争用 I2C。某个传感器未连接时系统不会停在启动页：MLX90640 失败时热图不可用，但仍可进入电量页面；CW2015 失败时电量页面显示错误状态。

### 热成像主界面

- MLX90640 原始分辨率为 `32 × 24`。
- 使用双线性插值将温度数据绘制为 `230 × 172` 热图。
- 热图横向方向已按当前 LCD 扫描方向修正。
- 显示中心四像素平均温度和当前帧最高温度。
- 显示传感器设置刷新率与实际完成显示的热图帧率，二者不一定相同。
- 自动识别连续高温区域，并绘制白色角标和区域平均温度。
- 最多标记 10 个高温区域；区域阈值为当前画面温差范围的高端 20%，且至少包含 8 个 MLX90640 像素。

主界面有三个触摸按钮：

| 按钮 | 功能 |
| --- | --- |
| 切换模式 | 按“伪彩 → 白热 → 黑热 → 医疗色板 → 伪彩”循环切换。这里的“医疗”仅为高对比度色板名称，不代表医疗精度。 |
| 帧率 | 按 `32 → 64 → 4 → 8 → 16 → 32 Hz` 循环设置 MLX90640 刷新率。 |
| 电量 | 进入 CW2015 电池状态页面。 |

热图色阶根据当前画面的最低温度和最高温度自动拉伸。因此颜色表示的是当前画面内的相对温差，不是固定的绝对温标。

### 电池页面

- 显示 CW2015 读取的剩余电量百分比。
- 显示电池电压和 CW2015 版本寄存器。
- 每秒更新一次数据。
- 进入电池页面后暂停 MLX90640 采集和热图绘制，以降低系统负载。
- 点击“返回热图”恢复热成像采集。

### 温度提示 LED

LED 为低电平点亮。提示逻辑使用回差，避免温度在阈值附近波动时频繁闪烁。

| LED | 点亮条件 | 熄灭条件 | 含义 |
| --- | --- | --- | --- |
| LED3 | 画面最高温度 ≥ 45 ℃ | 画面最高温度 ≤ 43 ℃ | 高温提示 |
| LED4 | 画面最高温度 ≤ 5 ℃ | 画面最高温度 ≥ 7 ℃ | 低温提示 |

该提示仅用于演示，不能替代经过认证的温度保护电路。

## 软件架构

项目使用 CMSIS-RTOS2 接口运行 FreeRTOS，主要任务如下：

| 任务 | 优先级 | 栈大小 | 作用 |
| --- | ---: | ---: | --- |
| `Init_task` | Above Normal | 6144 B | 启动界面、LED 流水、自检及传感器初始化 |
| `LVGL_USE_Task` | Normal | 4096 B | 运行 `lv_timer_handler()`，处理界面、动画和触摸事件 |
| `Img_Dis_Task` | Below Normal | 4096 B | 读取 MLX90640、计算温度、绘制热图，或轮询 CW2015 |

关键同步机制：

- 事件标志用于控制 LVGL 和图像任务的启动顺序。
- 二值信号量保护 LVGL 与 LCD，避免热图直写 LCD 时和 LVGL 刷新冲突。
- MLX90640 长数据读取使用 I2C1 RX DMA。
- LVGL 刷新和热图行传输使用 DMA2 Memory-to-Memory 搬运至 FSMC LCD 数据地址。
- DMA 失败或超时时会回退到 CPU 写屏，避免界面完全停止。

## 关键接口配置

以下配置来自当前 `RTOS_LCD/RTOS_LCD.ioc`：

| 项目 | 当前配置 |
| --- | --- |
| MCU | STM32F407VET6，LQFP100 |
| 内核时钟 | 168 MHz |
| I2C1 | Fast Mode，400 kHz，PB6/PB7 |
| I2C 上拉 | 外部 2.2 kΩ 上拉至 3.3 V |
| MLX90640 地址 | 7 位地址 `0x33` |
| CW2015 地址 | 7 位地址 `0x62` |
| I2C1 RX DMA | DMA1 Stream0 / Channel1，High priority |
| LCD 块传输 DMA | DMA2 Stream0，Memory-to-Memory，Half Word，Very High priority |
| LCD 总线 | FSMC 16 位并行总线 |
| 调试接口 | SWD |
| 串口 | USART1，PA9/PA10；当前应用未提供完整日志协议 |

STM32 HAL 的 I2C API 使用左移一位后的地址。文档、原理图和芯片资料中的 `0x33`、`0x62` 均为 7 位地址，不要在接线或 I2C 扫描结果中误写成 `0x66`、`0xC4`。

## 获取与编译

### 推荐环境

当前已验证环境：

- Keil µVision `5.43.1`
- ARM Compiler 5，`V5.05 update 1 (build 106)`
- Keil STM32F4xx Device Family Pack `2.13.0`
- ARM CMSIS Pack `6.2.0`
- STM32CubeMX `6.18.1`
- LVGL `8.3.11`

使用其他版本不一定失败，但首次复现建议先使用接近的工具版本。

### Keil 编译

1. 克隆或下载仓库。
2. 使用 Keil 打开 `RTOS_LCD/MDK-ARM/RTOS_LCD.uvprojx`。
3. 确认目标为 `RTOS_LCD`，并安装缺少的 STM32F4 DFP 和 CMSIS Pack。
4. 执行 Rebuild。
5. 编译成功后使用 ST-Link 下载，或烧录生成的 `RTOS_LCD/MDK-ARM/RTOS_LCD/RTOS_LCD.hex`。
6. 复位后观察启动自检页、四个 LED 和两路 I2C 检测结果。

`rtos_lcd_V3.07` 已在上述 ARMCC 5 环境完成构建，结果为 `0 Error(s), 0 Warning(s)`。链接结果约为：

- Code：281192 B
- RO-data：91552 B
- RW-data：976 B
- ZI-data：112680 B

### 使用 CubeMX 重新生成代码

CubeMX 工程文件为 `RTOS_LCD/RTOS_LCD.ioc`。重新生成前必须先提交或备份当前修改，因为 CubeMX 可能覆盖：

- `Core/Src/freertos.c`
- `Core/Src/gpio.c`
- `Core/Src/i2c.c`
- `MDK-ARM/RTOS_LCD.uvprojx`

本项目的 DMA、任务同步、启动自检和自定义源文件已经超出 CubeMX 默认生成内容。生成后应立即检查 Git diff，并确认 `boot_screen.c`、`boot_logo.c`、`cw2015.c`、`color.c` 和 `MLX.c` 仍在 Keil 工程中。

## 操作说明

1. 按 EPRO 和 BOM 完成硬件焊接与连接。
2. 确认 I2C 总线上拉至 3.3 V，MLX90640 和 CW2015 供电正确。
3. 烧录固件并复位。
4. 检查 LED1～LED4 是否依次点亮。
5. 检查启动页是否显示 `MLX:OK` 与 `CW:OK`。
6. 进入主界面后，将手或其他温差明显的物体放入 MLX90640 视场。
7. 使用“切换模式”选择色板，使用“帧率”选择传感器刷新率。
8. 点击“电量”查看 CW2015 数据，再点击“返回热图”恢复热成像。

设置为 32 Hz 或 64 Hz 不代表屏幕必然达到相同帧率。实际显示速度还受到 400 kHz I2C 带宽、两子页采集、浮点温度计算、双线性插值和 LCD 写入时间限制，应以界面显示的“热图 FPS”为准。

## 常见问题

### 启动页显示 `MLX:FAIL`

- 检查 MLX90640 电源、地线和排线方向。
- 扫描 7 位地址 `0x33`。
- 检查 PB6/PB7 和外部上拉电阻。
- 用示波器确认 SCL 接近 400 kHz，Fast Mode 上升时间应满足器件要求。
- 如果并联了多个模块自带上拉，确认等效阻值没有过低；不建议低于约 1 kΩ。

### 启动页显示 `CW:FAIL` 或电量页显示错误

- 扫描 7 位地址 `0x62`。
- 确认 CW2015 已正确供电并与电池共地。
- 驱动会先退出休眠、执行一次 Quick Start，再等待首组转换结果。
- `VER:0x00` 表示读到的版本寄存器值为零，不表示器件地址是 `0x00`。
- 常见错误中，`E:-2` 表示设备无应答，`E:-8` 表示版本值为 `0x00/0xFF`，`E:-9` 表示版本、电压或电量数据无效。

### 中文显示为方框

项目使用裁剪后的中文点阵字体，只包含界面实际使用的字符。新增中文文本后，需要重新生成：

- `lv_font_SourceHanSansCN_Light_2_12.c`
- `lv_font_SourceHanSansCN_Light_2_16.c`

同时确认字体源文件仍在 Keil 工程内。ARMCC 5 对源文件编码支持有限，运行时中文字符串建议使用 UTF-8 十六进制转义。

### 触摸没有反应或坐标错误

- 检查触摸控制器的 `PEN`、`CS`、`SCK`、`MISO` 和 `MOSI` 信号。
- 当前触摸输入通过软件时序读取，并依赖现有屏幕方向和校准参数。
- 更换不同型号的 LCD/触摸屏后，不能默认沿用当前坐标映射，应重新校准并检查 X/Y 是否交换。

### 热图卡顿

- 先查看“设置 Hz”和“热图 FPS”，不要只根据按钮设置值判断性能。
- 4 Hz 或 8 Hz 设置本身会造成较低刷新速度。
- 电量页面会主动暂停热成像，这是设计行为。
- 检查 I2C 是否发生 NACK、DMA 超时或降级到 CPU 写屏。

### 出现 HardFault

工程已启用 FreeRTOS 栈溢出检测，并保留 CFSR、HFSR、MMFAR、BFAR、PSP、MSP 等 HardFault 现场变量。调试时应先查看这些寄存器，不要只停留在 `HardFault_Handler()` 的死循环。

不要随意减小三个任务的栈。当前静态调用图给出的初始化任务最大栈深约为 3736 B，而任务配置为 6144 B。

## 已知限制与后续计划

- 当前温度计算固定使用发射率 `0.95` 和 `TA_SHIFT = 8 ℃`，尚未提供界面校准。
- 色阶为每帧自动范围，画面颜色不能直接跨场景比较绝对温度。
- CW2015 尚未写入针对具体电池的容量模型配置，显示精度需要结合实际电池验证。
- USART1 已由 CubeMX 初始化，但目前没有完整的日志输出模块或通信协议。
- 尚未实现 SD 卡记录。
- 触摸校准参数与当前屏幕组合相关，更换屏幕后需要重新验证。
- USART、SD 卡写入和电池模型标定仍属于后续扩展内容。
